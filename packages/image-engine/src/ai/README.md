# Optional local AI

The portrait engine is an actual MODNet ONNX graph running inside an application worker through ONNX Runtime Web 1.22.0. Users explicitly download 37,168,009 bytes (model plus runtime). Every asset is pinned and checked against a SHA-256 digest before it enters Cache Storage. Cancellation aborts downloads or terminates inference; deletion removes the model and runtime cache. Neither inference nor document pixels are sent to a model host. Cache Storage can be evicted by the browser; the UI checks installation state again when opened.

MODNet is a portrait matting model, so the UI calls its selection action **Select Person**. It does not claim arbitrary subject recognition or Adobe model equivalence. Inputs are normalized using the model's RGB mean/std of 0.5, resized to multiples of 32 with a 768-pixel longest-edge limit, and the output is bilinearly resampled to document resolution. Inference uses one WebAssembly CPU thread, avoiding WebGPU compatibility and cross-origin isolation requirements. The worker loads its JavaScript, loader, WASM and graph from locally cached blobs. A restrictive deployment CSP must allow the application worker, `blob:` module loading and WebAssembly compilation. Downloads need Hugging Face and jsDelivr access; ordinary inference needs no external network.

The worker receives a `SceneEncoder` packet for the inference viewport. Active-layer inference includes only the requested layer. Source files, embedded original bytes, selections and saved alpha channels are omitted. Tile copies transfer ownership to the worker, while the document's immutable pixel buffers remain attached on the main thread. Composite inference includes the visible render scene.

Remove Background creates an editable linked layer mask and preserves the underlying source pixels. A previously enabled mask is multiplied into the result. Select Person changes the separate document selection. Existing image-engine history supplies one undo step per accepted result. The dialog checks document ID and revision before applying an asynchronous result.

The generative option is a separate, optional **user-installed ComfyUI server**. It accepts only `localhost`, `127.0.0.1` or `[::1]` endpoints. It discovers installed checkpoints from `/object_info/CheckpointLoaderSimple`, uploads an image with an alpha-encoded inpainting mask, queues a real VAE/KSampler graph, polls only its prompt ID, and reads the returned image. Generative Fill uses the document selection; Expand extends the canvas on all sides and selects only the added border. Generated pixels occupy a new top layer, with alpha restricted to the selected region. The original layers remain editable. Input is limited to 1024 pixels and results are resized to document dimensions; fine-detail generation is best done on smaller documents.

ComfyUI setup is available from the dialog as an official download link and downloadable text instructions. Start a Python installation with `python main.py --listen 127.0.0.1 --enable-cors-header <LopeOS origin>`. Standard SD 1.x, SD 2.x and SDXL checkpoints are supported; their licenses and hardware requirements vary. Flux/custom multi-loader workflows are not supported. Cancellation removes only this client's queued prompt if possible. It never calls the global `/interrupt` endpoint; an already-running job may finish locally. ComfyUI retains uploads/outputs according to its own storage configuration.

## Verification

`node --test tests/image-editor/ai.test.ts` checks bounded preprocessing, linked masks, source preservation, immutable download metadata, loopback validation and the ComfyUI request/response protocol. `node tests/image-editor/ai-browser.mjs` uses the actual downloaded graph and runtime in Chromium; cached fixture bytes can be supplied at the `/tmp/lope-ai-*` paths referenced in the test, otherwise it downloads the pinned assets. It verifies model installation, real WASM inference without refetching external assets, generated-patch alpha, expansion geometry and cache deletion. The integrated application commands and dialog are also exercised: Download/Delete, Select Person, Remove Background, one-step Undo, cancellation, stale-document rejection, checkpoint discovery, Generative Fill and Generative Expand. The ComfyUI server responses are mocked; the portrait model and worker execution are real. The generated report is `docs/image-editor/local-ai-verification.json`. End-to-end diffusion needs an installed ComfyUI/checkpoint and is not claimed by these tests.

An additional single-photo probe (`node tests/image-editor/ai-portrait-browser.mjs`) uses the NASA photograph of Eileen Collins distributed as [scikit-image's astronaut sample](https://scikit-image.org/docs/stable/api/skimage.data.html#skimage.data.astronaut). That primary dataset documentation identifies it as public domain. The photo and derived source/matte/cutout comparison stay in `/tmp`; no third-party photograph is bundled in the application. In Chromium, the actual 512×512 model run took about 1.33 seconds and classified 53.2% of the image above half opacity. Two coarse face/suit patches averaged alpha 255; two background patches averaged 0. Visual inspection showed the face, hair, suit and held helmet largely isolated from the flag/shuttle background, with soft hair edges and low-opacity artifacts around a bright lower glove/connector requiring refinement. This is a qualitative check of one photograph, with no ground-truth matte or Photoshop-equivalence claim; detailed source/license/measurements are in the report's `portraitQuality` field.
