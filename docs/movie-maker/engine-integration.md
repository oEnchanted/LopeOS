# Movie Maker engine integration

Movie Maker owns `packages/movie-maker` (simple ordered sequence and saved decisions) and `packages/media-engine` (its adapter for canvas composition and audio scheduling). The concurrent converter implementation owns `packages/media-service`, the codec registry, input probing, generic jobs, and Mediabunny dependency. The concurrent professional editor owns `packages/video-engine`.

Movie Maker does not introduce an FFmpeg copy or a second muxer. `packages/media-engine/src/shared-codecs.ts` consumes only `packages/media-service/src/index.ts`: `probe`, `LocalMediaService`, output/container/canvas/audio primitives, and encoder capability checks. MediaService owns codec capability detection, orientation/pixel-aspect-aware video decoding, and its bounded decoded frame/PCM caches. The Movie Maker adapter owns rendering its simple sequence and feeding those rendered frames into the shared output primitives.

All Movie Maker output timeline decisions use integer frames at the project's rational frame rate; slow-speed splits may retain fractional source-frame offsets. Export converts output frame timestamps back into the project time base, calls the same `renderFrame` evaluator as preview, and passes those frames to the shared encoder. `mixAudio` applies source offsets, playback speed, clip-anchored lane timing, fades, and audio emphasis to the same edit decisions. It asks the shared decoder for bounded PCM windows and yields between two-second output blocks. Preview and export consume that identical mixed audio. Shared video decoding applies orientation and pixel aspect metadata before the app's explicit rotation/fit.

Output is genuine MP4 with H.264/AAC where both shared encoder probes succeed, or WebM with VP8/Opus. The adapter defaults to WebM for backwards compatibility; the application can prefer MP4 after probing. Unsupported encoders produce an actionable error; there is no screen recording or extension relabeling fallback. Every output is independently reopened, its packets counted, and duration, dimensions, frame-rate timestamps, video/audio codecs, and decoded audio checked before download. The full three-minute fixture is verified as WebM; a separate nine-second title/photo/video/music smoke test verifies real MP4 output and independent AAC decoding in `mp4-verification.json`.

The browser implementation uses shared asynchronous WebCodecs, a six-image cache, shared eight-handle/24 MB PCM caches, frame-by-frame output backpressure, and a dedicated worker for audio resampling, mixing, fades, ducking, and limiting. Exactly one two-second PCM block is in flight. Only copied source buffers are transferred; the shared decode cache remains intact. Abort, disposal, decode errors and worker errors reject pending work and release the worker. A pure fallback uses identical math in environments without workers. The canvas/text compositor remains on the main thread.

`audio-worker-verification.json` proves zero sample difference from the pre-worker mixer and the pure fallback, intact original PCM buffers, cancellation/disposal rejection, and a playable short WebM export. The MP4 smoke test also passes after worker integration. The output uses an in-memory target with a 512 MB estimated cap, the full mixed stereo output buffer is limited to 20 minutes, and at most 64 simultaneous sound segments are mixed. These are explicit bounds, not claims of unlimited project size.
