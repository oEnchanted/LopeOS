# Movie Maker

LopeOS Movie Maker is the simple sequence editor. Launch **Movie Maker**, add photos or videos, arrange the storyboard, add text and music, preview, and choose **Save movie**. **Save project** retains editable decisions. The workspace is an opaque light ribbon, left preview and wrapping storyboard; the LopeOS window supplies the shared glass material.

The implementation lives in `apps/web/src/apps/movie-maker`, its frame-based project model and local storage in `packages/movie-maker`, and its compositor/mixer/export adapter in `packages/media-engine`. The media adapter consumes the shared `packages/media-service` codec/probe/cache service. Generic conversion remains owned by that service.

## Historical baseline

The baseline is **Windows Movie Maker 2012 / Windows Essentials 2012**. Microsoft's [2012 introduction](https://blogs.windows.com/windowsexperience/2012/08/07/introducing-the-new-windows-photo-gallery-and-movie-maker/) establishes three audio sources, narration recording/import, video and music waveforms, audio emphasis, text outlines, H.264 output and Windows 8 stabilization. The [2010 article](https://blogs.windows.com/windowsexperience/2010/06/24/my-thoughts-on-the-new-windows-live-essentials/) supplies earlier context for AutoMovie themes and custom export settings; its geometry is not evidence for 2012.

Microsoft [ended Essentials support on January 10, 2017](https://support.microsoft.com/en-us/windows/apps/support-for-windows-essentials-apps). This is an interface reference, not an installer or online publishing integration. The [modern Photos/Clipchamp guidance](https://support.microsoft.com/en-us/clipchamp/windows-photos-app/create-films-with-a-video-editor) describes separate products.

Exact historical pixel parity is **UNVERIFIED**: the official pages retrieved did not supply a version-matched capture with known dimensions, scale and full tab groups. [reference-manifest.json](reference-manifest.json) records the evidence, assumptions and matching protocol. LopeOS adaptations include Files/download destinations, its own project format, an explicitly modern portrait preset, and capability-tested MP4/WebM output. No `.wlmp` compatibility or stabilization is advertised.

## Projects and privacy

`.lopemovie` is an allowlisted version-1 JSON decision file. It stores rational project frame rate, source references, sequence trims, transforms, effects, transitions, text, music/narration and output settings. It does not contain rendered video. Referenced sources are stored locally in IndexedDB; a decision file opened in another browser may need relinking.

`.lopemoviebundle` embeds all referenced original media with SHA-256 integrity checks and the decision file. It is portable and can reopen without the original browser's cache. The current portable limit is 256 MB of original media. IndexedDB autosave commits media and project decisions in one transaction. A failed transaction preserves the previously acknowledged project; errors direct users to download a portable copy.

Imports and rendering stay local. Only a user-initiated narration recording asks for microphone access; tracks stop when recording ends or the app closes. Bundled sample assets are ordinary same-origin application files. There is no invisible upload or remote fallback.

## Reproducible sample

Choose **Load sample project**. “A little adventure” has exactly 5,400 project frames at 30 fps (3 minutes): eight original landscape illustrations in JPEG/PNG/WebP, two actual VP8/Opus clips, camera sound, an original PCM music bed, spoken narration, an editable title and credits, four clip-anchored captions, source trims, fades/dissolves, pan/zoom and visual effects.

The editable [sample project](sample.lopemovie), [portable bundle](sample.lopemoviebundle) and [rendered movie](sample-output.webm) are generated by the acceptance run. The two source clips and narration are bundled under `public/movie-maker-sample`. Landscape and music generation is deterministic in `sample.ts`. The videos are generated through the same offline renderer, never by recording playback.

To regenerate the two source videos with the development server running:

```sh
node tests/movie-maker/generate-sample.mjs
```

The included narration is synthetic speech generated locally with the installed macOS voice, not a microphone recording. The source sentence is: “Every little adventure starts with a single step. We followed the river into the hills, watched the clouds move across the mountains, and took our time on the way home. These are the moments we wanted to remember.” Recreate it with `say -r 155 -o /tmp/lope-movie-narration.aiff '…'` and `afconvert -f WAVE -d LEI16 /tmp/lope-movie-narration.aiff public/movie-maker-sample/narration.wav`; voice availability changes the exact waveform, so the checked-in WAV is the stable test asset.

## Verification

```sh
npm run test:movie-maker
# In another terminal, or use an existing server:
./node_modules/.bin/vite --config tests/movie-maker/vite.config.ts
node tests/movie-maker/engine-browser.mjs
node tests/movie-maker/audio-worker-browser.mjs
node tests/movie-maker/mp4-browser.mjs
node tests/movie-maker/persistence-browser.mjs
node tests/movie-maker/ui-browser.mjs
node tests/movie-maker/failure-browser.mjs
node tests/movie-maker/relink-browser.mjs
```

Set `MOVIE_TEST_URL` to use a different development origin. The browser tests use Playwright Chromium. The engine run produces `engine-verification.json`, a full three-minute 720p WebM export, a portable bundle and an actual rendered checkpoint. It independently decodes exported frames and audio in the browser, checks metadata, compares eight preview/output points, and exercises corruption, missing assets, cancellation, reload and injected storage failure. `mp4-verification.json` records a separate real 9-second 720p H.264/AAC export with 270 packets and audible decoded audio. The UI run records its own workflow evidence and screenshots. Machine-operated workflow evidence is not a human novice usability study.

An isolated production bundle can be checked independently of other unfinished applications in the workspace:

```sh
node tests/movie-maker/production.mjs
# While its localhost preview is running:
MOVIE_TEST_URL=http://127.0.0.1:5179 MOVIE_PRODUCTION=1 node tests/movie-maker/ui-browser.mjs
```

This bundles the actual Movie Maker and shared packages with a test-only SDK host into `/private/tmp/lope-movie-maker-production`; it does not deploy or publish.
