# Lightroom architecture

`apps/web/src/apps/lightroom/manifest.ts` registers `lope.lightroom` through the existing extensions registry. Commands are window-scoped by the shell; single-letter and editing shortcuts leave text, numeric and dialog inputs alone. Source association selection is exposed in Files → Open With. The Dock migration adds the new app once and then respects later removal.

`library.ts` separates IndexedDB `assets`, immutable managed `originals`, `albums`, and import `jobs`. UUID identity is independent of filenames. SHA-256 determines content duplicates and verifies relinking and backup. A linked workspace asset retains a path/version and is checked against its content hash before processing; it is not silently reinterpreted after replacement. No original bytes are stored in localStorage. Small workspace preferences and handoff references use the OS settings service.

Asset and original insertion is transactional. Recipe/metadata updates are serialized and awaited by the app close guard. Failed writes remain in a pending map; the UI reports Save failed and offers retry. Browser reload/unload warns while work is unsaved. IndexedDB persistence is still subject to browser quotas, eviction and clearing; the settings surface exposes usage, persistence requests, and backup/restore.

The import worker decodes one item at a time. Preview and export workers own at most one cached decoded source each, preventing full floating-point copies of every imported photo. Previews coalesce to the latest requested recipe. Hash/source caches are scoped to a single active original. Original transfer, basic library access and core export need no WebGPU. Heavy decode, editing, analysis and encoding run in workers; LibRaw uses its own nested WASM worker.

## Independent processing graph

1. Recognize the container, enforce supported-variant/dimension limits, extract available metadata, decode full pixels, and apply source orientation. Camera RAW uses LibRaw's sensor unpack/demosaic/characterization path and returns 16-bit linear sRGB, never an embedded JPEG substitution. Browser raster decoding delegates its input-profile conversion to the browser. Native TIFF/PNG16 accept only their documented color variants.
2. Retain the immutable source and form Float32 linear-sRGB RGBA working data. A preview may downsample that source. Each render starts from this data rather than a previously rendered export.
3. Apply retouch source sampling, then standard noise reduction in the source image domain. `noise.ts` performs a classical 5×5 bilateral filter with independent luminance/chroma strengths and alpha-aware edge weights. It requires no learned model or network request, preserves Float32 headroom, and bypasses zero settings. Sharpening/texture and wider clarity neighborhoods then operate on the filtered image. Detail radii scale with the source/preview size. Full image tiling and color-managed wide-gamut storage are future work.
4. Map output positions through crop, quarter-turns/flips, straightening, perspective and manual radial distortion. Masks and sampled retouch coordinates remain normalized to the oriented source. The same geometry functions map overlays and samplers.
5. Apply original Lope profile behavior, relative decoded white balance and linear exposure, independent tone functions and perceptual tone curves; then color mixing/grading and local mask adjustments. Temperature uses a relative scale after camera/browser decode; it is not a calibrated Kelvin camera-RAW control.
6. Apply vignette, manual channel alignment and deterministic source-coordinate grain. Compute the RGB histogram and clipping visualization from current rendered pixels. The histogram is a preview-resolution measurement, not a sensor histogram.
7. For export, use the same recipe at full supported resolution, resize to the requested output, sharpen at the output resolution and composite only the text watermark coverage into floating-point pixels. Encode real output bytes and tag sRGB or linear-sRGB as appropriate. Integer/SDR outputs intentionally clamp output range; 32-bit float TIFF can retain numerical headroom.

Neighborhood sampling and grain are consistent in coordinate intent across preview/export but not promised pixel-identical after downsampling. Adobe processing algorithms, process versions, camera profiles, reconstruction, masking and AI models are not reproduced numerically. LibRaw's integer output stage has its own recovery/headroom limits.

## Optional local AI denoise

`DenoiseDialog.tsx` controls a dedicated, cancellable `denoise-worker.ts`. The first-use action downloads four same-origin static assets, verifies every byte count and SHA-256, and atomically stores their binary buffers in the separate `lope.photo-ai-models.v1` IndexedDB database. No photo is part of those requests. Binary buffers avoid filesystem-backed Blob serialization failures in WebKit; reads reconstruct correctly typed Blobs. A failed or cancelled installation leaves no partial installed record. The runtime verifies cached assets again before importing the self-contained ONNX Runtime module from a Blob URL and loading the pinned FFDNet weights. CPU WASM runs single-threaded without WebGPU, cross-origin isolation or a CDN. Terminating the worker cancels inference; the client revokes its module/WASM Blob URLs.

The worker decodes the immutable oriented source and rejects transparent or out-of-range/HDR working pixels. It converts linear sRGB into the model's normalized sRGB domain, packs 160×160 planar tensors, and supplies the chosen noise standard deviation divided by 255. Each global 96×96 valid core has a 32-pixel replicated halo. Even tile origins preserve pixel-unshuffle phase; preview and full inference use the same global grid and source coordinates. Amount blends the model's clean RGB output with the original in linear Float32 precision. The 100% preview shows unedited source pixels and instant Amount changes; noise/focus changes are debounced and automatically coalesced to the latest requested settings while controls remain editable. It is not a resized proxy.

Full processing encodes an unedited TIFF16 derivative with the source's oriented dimensions, then carries the source recipe, rating, labels, keywords and album membership to a new asset. This preserves crop and mask coordinates while avoiding applying edits twice. The saved asset links to its source and records model/runtime/decoder versions, hashes, parameters and processing time. Asset and TIFF bytes commit in one transaction. A failed save retains the completed result for retry without inference. Saved derivatives decode and export without the AI package. Clearing the package never deletes originals or derivatives. See [AI Denoise](ai-denoise.md) and [the pinned model manifest](denoise-model-manifest.json).

## Interchange and failure boundaries

XMP importing maps a documented subset of Camera Raw attributes approximately, imports ratings/labels/keywords, reports unknown develop fields, and retains the original sidecar. Export stores mapped attributes plus a namespaced Lope recipe. It does not claim an Adobe profile/process/mask round trip. Rendered exports omit private source metadata by default; original downloads retain exact source bytes.

The ZIP writer uses stored entries, CRC32, stable paths and a portable manifest. Restoration accepts this specific format, bounds archive/manifest sizes, validates recipes and all original hashes before writing, and can be re-run after interruption. It does not execute archive paths or overwrite workspace sources.

Image Editor handoffs use actual native files and file-service change notifications. Returned revisions become managed snapshots linked to their original photo, so further editor saves cannot mutate an earlier derivative's saved bytes. This is RGB/8 interchange because that is the existing Image Editor's supported native precision.

`jobs.ts` defines optional provider identity, versions, pricing/data flow, asset references/hashes, explicit upload authorization, progress, provenance, cancellation and retry. No provider is installed or called. AI, sharing, sync and camera credentials do not enter frontend settings or bundles. A future remote implementation must enforce upload authorization and hold credentials in the service, then add exact model/codec fixtures before enabling controls.
