# Linux streaming release gate (not executed on the Mac development host)

Run the actual Docker/Kubernetes worker, behind the authenticated LopeOS gateway, on a disposable test profile. Run this checklist in Chromium, Firefox and Safari on both standard and high-DPI displays. Preserve engine/transport versions, client versions, logs with content removed, and pass/fail evidence in `docs/browser.md` before marking any transport capability tested.

1. Open a public HTTPS JavaScript test application with an input form, same-document history, cross-origin iframe, websocket echo, service worker, upload input, a downloadable file and ordinary audio/video. Do not grant a private-network bypass for the fixture.
2. Observe a real negotiated Selkies media pipeline. In its core, send `getStats` via same-origin `postMessage` and verify `stats.data.clientFps > 0`; verify moving content rather than a static frame. Inspect the network: media arrives on the Selkies WebSocket and there are no recurring screenshot requests.
3. Click the form using the streamed surface. Type accented text, CJK with a real OS IME, emoji, shift selections and modifier shortcuts. Submit and verify the actual page response. Test pointer edges, text drag selection, wheel, touch scrolling, right-click website context menu, copy/paste with explicit host consent, and lost-key recovery after switching focus.
4. Follow links, use back/forward and redirects. Trigger a popup and a cross-origin OAuth test flow. Verify `window.opener` remains intact until the website itself severs it. Confirm address/title/loading/back/forward indicators against Chromium state. Do not use successful test popups as proof that all OAuth providers allow a remote browser.
5. Resize the LopeOS window, change display scale, and repeat pointer tests. Verify the remote viewport actually resizes and that no browser toolbar is cropped into page content. Test a second display and reconnect. Check whether the kiosk window follows XRandR display changes.
6. Play WAV/Opus and VP8/WebM samples. Confirm motion and decoded audio with both Selkies telemetry and audible output in the host. Verify autoplay unlock, mute/unmute, tab changes, sustained playback and reconnect. Repeat with H.264/AAC only if the installed Chromium build advertises those codecs; record each result separately. Test audio echo and lip sync.
7. Start and cancel a real download, complete another into the owner’s workspace through Agent 2’s bridge, and use Show in Files. Select a workspace upload and a device upload. Verify binary hashes, filename, no overwrite, file-size limits, cancellation/failure UI, and that no unselected file appears in the worker.
8. Disconnect networking and restore it. Verify the disconnected state appears, the stream reconnects, metadata remains authoritative, modifiers do not stick, and normal tabs/cookies survive worker restart. End a private session, verify all its context/staging data is gone, then force worker idle cleanup and verify its temporary directories are destroyed.
9. Test expired credentials, wrong-owner requests and WS upgrades, direct Selkies/CDP access, DNS rebinding to metadata/private services, service-worker and WebSocket private-network attempts, and cross-session file IDs. Confirm browser sandbox state inside Chromium and verify the cluster’s egress policy actually blocks private ranges.
10. Verify keyboard access to all chrome controls and menus, focus trapping/return for dialogs, screen-reader announcements of loading and errors, and Open in host browser. Remote webpage semantics are currently unavailable to local screen readers; record this limitation explicitly.

Release remains gated on this checklist. Headless engine tests do not establish streaming/audio, real IME, real device forwarding, browser-specific accessibility, or production container isolation.
